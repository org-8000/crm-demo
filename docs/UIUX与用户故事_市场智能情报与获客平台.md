# 市场智能情报与获客平台 — UI/UX 设计与用户故事

> 配套《技术设计文档》。前端栈：Next.js(React)。围绕"**洞察即产出 + 人工接管**"设计。
> 版本：v1.0 ｜ 2026-08

---

## 1. UX 设计原则

1. **洞察优先，而非数据表格**：首屏看到的是"可行动的判断卡片"，不是原始爬取数据。
2. **证据一键可溯**：每条结论旁必有"证据"入口，点开看原文出处（建立信任、对抗幻觉）。
3. **人在回路是显性动作**：需要人确认/接管的事项集中到一个队列，不散落各处。
4. **置信度可视化**：高/中/低置信用颜色+分值表达，低置信默认引导人工复核。
5. **合规状态透明**：每条数据标注来源与合规等级（🟢🟡🔴），高风险操作二次确认。
6. **模块串联无缝**：从一张卡片能一键跳到下游动作（名单→研判→准入→触达）。
7. **少即是多**：与"组件少而精"呼应，界面信息密度克制，一屏一焦点。

### 4.2 统一洞察卡片 InsightCard（六模块通用组件）
> 前端只维护**一个**卡片组件，靠 `module` + `verdict` 渲染差异，呼应统一 `Insight` 模型。
```
┌─ InsightCard ─────────────────────────────────────────────┐
│ [模块标签 M3] [🟢合规]              置信度 ●●●●○ 0.82        │
│ 主题：Acme Payments (新加坡)                                │
│ ─────────────────────────────────────────────────────────  │
│ 判断（verdict，按模块渲染）：                                │
│   • 业务聚焦：跨境收单 + 钱包                                │
│   • 合作切入点：① 其正申请 MPI 牌照 ② 缺 ISO20022 能力      │
│   • 风险提示：⚠ 母公司涉某制裁关联（待核）                   │
│ ─────────────────────────────────────────────────────────  │
│ 证据链: [官网] [MAS公告] [Finextra报道]  ← 点开看原文快照     │
│ ─────────────────────────────────────────────────────────  │
│ 操作: [查看合规准入⑤] [加入触达⑥] [标记已读] [需人工复核]    │
└───────────────────────────────────────────────────────────┘
```
- **置信度**：●○ 点阵 + 数值；<0.6 卡片描边变黄并默认勾选"需人工复核"。
- **合规角标**：🟢🟡🔴 悬浮显示来源与依据。
- **操作区**：直接暴露"串联下游"的动作，减少跳转。

## 5. 核心交互流：人工接管队列（Review Queue）

> 承载全平台 HITL（对应 `agno_approvals` + `insight.needs_human`），是"Agent 自动 + 人工接管"理念的 UX 落点。

```
┌ 接管队列 ─────────────────────────────────────────────┐
│ 筛选: [全部|M2|M6|低置信]   排序: 紧急度▾                │
├────────────────────────────────────────────────────────┤
│ 🔴 [M6] 触达文案待批准 · 发给 John(Acme CTO)             │
│     摘要+研判上下文  → [批准] [编辑后批准] [升级人工] [拒绝]│
│ 🟠 [M2] 招标线索待确认 · 某行 截止9/15 · 置信0.55        │
│     → [确认为有效] [忽略] [标记误报(反馈模型)]            │
│ 🟡 [M3] 低置信研判待复核 · Beta Pay 母公司关联存疑        │
│     → [采纳] [修正判断] [补充证据]                       │
└────────────────────────────────────────────────────────┘
```
交互要点：
- 每项都带**决策所需的最小上下文**（不用跳转即可判断）。
- **反馈闭环**：`标记误报/修正判断` 写回 `agno_learnings`，让系统越用越准。
- **批量操作**：同类可批量批准/忽略。
- 状态流转：`new → reviewed → actioned/dismissed`，与 `insight.status` 一致。

## 6. 用户故事（User Stories + 验收标准）

> 格式：作为 <角色>，我希望 <能力>，以便 <价值>。附验收标准(AC)。

### 底座 / 通用
- **US-0.1** 作为任意用户，我希望每条洞察都能看到证据来源，以便信任并复核结论。
  - AC：卡片必有"证据"入口；点开显示来源 URL、快照片段、抓取时间；无证据的洞察不予展示。
- **US-0.2** 作为用户，我希望看到每条结论的置信度，以便决定是否人工复核。
  - AC：显示 0–1 分值与点阵；<0.6 自动标记"需人工复核"并进接管队列。
- **US-0.3** 作为管理员，我希望看到并控制每个数据源的合规等级，以便规避法律风险。
  - AC：源列表显示 🟢🟡🔴；🔴 源需显式开启 flag + 记录审计；关闭时相关模块运行合规子集。

### 模块① 行业情报（Mia）
- **US-1.1** 作为分析师，我希望每天自动收到支付行业 Top3 精选认知，以便省去人工刷平台。
  - AC：每日 cron 产出；含"独特认知/大V观点/为何重要";可一键"转研判"。
- **US-1.2** 作为分析师，我希望过滤掉噪音只看关键观点，以便高效。
  - AC：SignalAgent 去噪；可按大V/媒体/主题筛选；可对结果点"没用"反馈以优化。

### 模块② 招标监控（Mia/Sam）🔴
- **US-2.1** 作为分析师，我希望第一时间收到银行招标线索并结构化展示，以便不错过窗口。
  - AC：命中即通知（含招标方/标的/金额/截止倒计时）；默认进接管队列人工确认。
- **US-2.2** 作为管理员，我希望群聊/私域监控默认关闭且需审批开启，以便合规可控。
  - AC：`ENABLE_M2_GROUP_MONITOR=false` 时该源不采集；开启需二次确认并留审计。

### 模块③ 客户研判（Ben）
- **US-3.1** 作为 BD，我希望输入机构名就得到画像+切入点+风险，以便快速判断商机。
  - AC：输入机构名(+国家/模式)→ 返回结构化 InsightCard；含 ≥1 切入点、风险提示、证据链。
- **US-3.2** 作为 BD，我希望研判过程可见，以便理解 AI 依据。
  - AC：展示实时步骤（采集/检索/研判）；可查看 trace。
- **US-3.3** 作为 BD，我希望一键把该客户带入合规准入与触达，以便打通流程。
  - AC：卡片有"查合规准入⑤""加入触达⑥"按钮，携带上下文跳转。

### 模块④ 峰会商机（Ben）
- **US-4.1** 作为 BD，我希望上传峰会议程/名单就自动筛出匹配 ICP 的机构，以便精准获客。
  - AC：解析议程→抽取机构/人→按 ICP 规则打分→列出命中项；支持一键批量转③研判。
- **US-4.2** 作为 BD，我希望自定义 ICP 规则，以便匹配我的目标画像。
  - AC：设置页可配置行业/地区/规模/业务方向等规则；即时预览命中数。

### 模块⑤ 合规准入（Chloe）
- **US-5.1** 作为拓展负责人，我希望输入目标国家+业务模式得到准入清单，以便前置评估风险。
  - AC：输出牌照/报文标准/数据合规/业务限制四类，每条附监管原文证据；含就绪度摘要。
- **US-5.2** 作为拓展负责人，我希望订阅某国监管变更，以便持续跟踪。
  - AC：可对某国开启 cron 监控；有变更时通知并生成新洞察。
- **US-5.3** 作为拓展负责人，我希望把准入清单导出/关联到具体客户，以便对内共享。
  - AC：支持导出 PDF；可关联到 M3 某机构研判。

### 模块⑥ 智能获客（Ben/Sam）🔴
- **US-6.1** 作为 BD，我希望基于研判上下文自动生成个性化触达文案，以便提高触达质量。
  - AC：文案引用 M3 切入点；显示意向研判等级；发送前必经审批。
- **US-6.2** 作为管理员，我希望自动发送默认关闭，仅在开启后受限速执行，以便合规安全。
  - AC：`ENABLE_M6_AUTOSEND=false` 时只出草稿；开启后真人账号限速发送 + 审计。
- **US-6.3** 作为 BD，我希望对方出现意向时被提醒接管，以便及时跟进不漏单。
  - AC：回复监测识别高意向→进接管队列并通知→附完整对话与研判上下文。

### 跨模块串联
- **US-X.1** 作为 BD，我希望"峰会名单→逐个研判→合规准入→触达"一条链走完，以便端到端获客。
  - AC：④命中项批量进③；③高 fit 项一键进⑥；③按国家自动关联⑤结果；全链路数据以 `org/person/insight` 贯通。

## 7. 端到端场景演练（Narrative Walkthrough）

### 场景 A：新国家拓展（Chloe + Ben，全绿色合规）
1. Ben 在 **M4** 上传"新加坡金融科技节"议程，系统抽出 60 家参会机构，ICP 打分筛出 12 家。
2. Ben 一键"批量转研判"，**M3** 逐家生成画像卡；Acme Payments 的 fit_score 0.82，切入点="正申请 MPI 牌照 + 缺 ISO20022"。
3. Acme 卡片点"查合规准入"，**M5** 自动按"新加坡+跨境收单"生成准入清单（牌照/报文/数据/限制，附 MAS 原文）。
4. Ben 点"加入触达"，**M6** 生成引用切入点的文案；因 `AUTOSEND` 未开，文案进**接管队列**；Ben 编辑后批准。
5. 全程数据经 `org→person→insight` 贯通，Sam 在概览看到"1 条链路完成、3 条待接管"。

### 场景 B：招标线索捕获（Mia + Sam，含高风险模块）🔴
1. **M2** cron 每 30 分钟扫描公开社媒信号，命中"某行拟启动跨境支付系统招标"。
2. 结构化为线索卡（招标方/标的/截止 9/15，置信 0.55），因低置信+高风险 → 进**接管队列**并即时通知。
3. Mia 在队列核实原文证据，点"确认为有效"→ 状态转 actioned，并一键"转研判"关联该银行。
4. 若管理员未开启群聊监控 flag，则该模块仅展示公开社媒信号，界面提示"群聊源未启用（合规）"。

### 场景 C：每日情报早报（Mia，绿色为主）
1. 每日 08:00 **M1** 自动产出行业 Top3，推送到概览首屏 + 飞书。
2. Mia 浏览"独特认知/大V观点/为何重要"，对一条点"转研判"生成潜在客户线索。
3. 对一条无价值的点"没用"，反馈写回 `agno_learnings`，次日推送更精准。

## 8. 视觉与可用性规范（要点）

- **色彩语义**：🟢低风险/正常、🟡中风险/中置信/待确认、🔴高风险/紧急；置信度用同一套色阶。
- **空状态**：每个模块首用给出"示例洞察 + 引导 CTA"，降低上手门槛（呼应"新人快速上手"痛点）。
- **可解释性**：Agent 运行显示步骤条 + trace 链接，避免"黑箱"。
- **可访问性(a11y)**：语义化标签、键盘可达、对比度达标、图标配文字。
- **响应式**：桌面为主（分析/审批场景）；概览与接管队列适配移动端只读+审批。
- **国际化**：中文优先，字段/清单支持中英（跨境场景）。
- **加载体验**：长任务（研判/准入）用流式步骤反馈，而非空白 loading。

## 9. 与技术底座的对应关系

| UI 元素 | 技术底座支撑 |
|---|---|
| 统一 InsightCard | 统一 `Insight`/`Evidence` 模型（§4.5 技术文档） |
| 接管队列 | Agno `approvals`(`agno_approvals`) + `insight.needs_human` |
| 实时步骤条 | Agno `traces`/`spans` |
| 每日 Top3 / 定时监控 | Agno `schedules`(cron) |
| 证据链点回原文 | `Evidence.source_url` + `ingestion_log` |
| 合规角标/开关 | 合规网关 + feature flags |
| "转研判/加触达"串联 | `org/person/insight.linked_org` 贯通 |
| ICP 规则 / 源管理 | `watch_source` + 规则配置 |
| 越用越准（反馈） | Agno `learnings`(`agno_learnings`) |

> 前端组件保持"少而精"：一个 InsightCard + 一个 ReviewQueue + 各模块输入面板，即可覆盖六模块，与后端统一模型一一对应。
