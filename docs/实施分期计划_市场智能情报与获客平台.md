# 市场智能情报与获客平台 — 实施分期计划（Implementation Roadmap）

> 配套《技术设计文档》《UI/UX 与用户故事》。栈：Python + Agno(AgentOS) + Next.js + PostgreSQL(pgvector)。
> 原则：**底座先行 → 低合规风险模块先落地(MVP) → 逐步串联 → 高风险模块最后且默认安全子集**。
> 工期为**相对估算**（人天/周），非承诺日历；按 1 个小团队（2 后端 + 1 前端 + 1 全栈/算法，共 ~4 人）测算。
> 版本：v1.0 ｜ 2026-08

---

## 0. 分期总览

| 期 | 名称 | 核心范围 | 模块 | 合规基线 | 估算 |
|---|---|---|---|---|---|
| **P0** | 工程底座 | 3 组件打通 + 共享底座 + CI/CD | 无业务模块 | 🟢 | ~3 周 |
| **P1（MVP）** | 客户研判 + 合规准入 | ③⑤ 端到端真实数据 + 串联 | ③⑤ | 🟢 全绿 | ~4 周 |
| **P2** | 商机扩展 | ④峰会 + ①情报(媒体源) | ④① | 🟢/🟡 | ~4 周 |
| **P3** | 获客与监控（安全子集） | ⑥文案+接管 + ②公开信号 | ⑥② | 🟡（高危功能关闭） | ~4 周 |
| **P4** | 高风险增强（可选做） | ⑥自动发送 + ②群聊监控 | ⑥② | 🔴 需法务+flag | ~3 周 |
| **P5** | 硬化与运营化 GA | 性能/安全/评估/多租户/运营 | 全部 | 🟢 | ~3 周 |

```
P0 底座 ─┬─ P1 ③⑤(MVP) ── P2 ④① ── P3 ⑥②安全子集 ── P4 高风险增强 ── P5 GA
        └─ 横向工作流(贯穿全程)：合规 · 可观测 · 评估(Evals) · 安全
```

> **关键路径**：P0 → P1；P2 依赖 P1 的③；P3⑥ 依赖 P1③/P2④ 的线索；P4 依赖 P3 且需法务放行。

## P0 · 工程底座（Foundation）

**目标**：把"3 组件 + 共享底座"一次性搭好，后续模块只做增量编排。

**范围**
- Docker Compose：`web(Next.js)` + `agentos(FastAPI/Agno)` + `postgres(pgvector)`。
- AgentOS 装配 + PG 连接；`auto_provision_dbs` 建 `agno_*` 表；业务 DDL 迁移（§5 技术文档）。
- 共享底座骨架：采集 Tools 接口、提取 Pipeline(GLiNER2+LLM)、Knowledge/pgvector、`Insight/Evidence` 模型、合规网关 + feature flags。
- 前端骨架：布局/导航、统一 `InsightCard`、`ReviewQueue` 空壳、BFF 代理 + 鉴权(`OS_SECURITY_KEY`)。
- 横向：CI/CD、代码规范(uv/ruff/eslint)、`.env` 模板、日志与 OpenTelemetry traces、密钥管理。

**交付产物**
- 可运行的 `docker-compose up` 全栈环境（README + 一键脚本）。
- PG schema 迁移脚本 + ER 图。
- 底座 SDK：`core/tools`、`core/extract`、`core/knowledge`、`core/models.py`、`core/compliance.py`（含单测）。
- 前端骨架：导航 + InsightCard 组件 + Storybook 示例 + 假数据渲染。
- CI 流水线（lint/test/build）+ 部署手册。
- **合规基线文档**：数据源分级表、PII 留存策略、feature flag 清单。

**验收标准（Exit Gate）**
- 一条"假 Insight"能从 API → 落 PG → 前端 InsightCard 渲染 + 证据链点开。
- AgentOS `schedules`/`approvals` 冒烟通过（能建 cron、能产生一条待审批）。
- CI 全绿；`.env.example` 齐全；无明文密钥入库。

**风险/缓解**：Agno 2.0 版本特性核对（以官方为准）→ P0 首日做技术验证 spike。

## P1 · MVP：客户研判③ + 合规准入⑤（含串联）

**目标**：交付**可对外演示、真实数据跑通**的两个低风险模块，体现"AI 把信息转成可行动洞察"。

**范围**
- ③ 客户研判：输入机构名(+国家/模式)→ Team(采集+研判+风险)→ 画像/切入点/风险 InsightCard + 实时步骤条。
- ⑤ 合规准入：输入国家+业务模式 → `regulator_fetch`+RAG(`kb_payment_ontology`)→ 牌照/报文/数据/限制清单(附监管原文)。
- 知识库：初始化 `kb_payment_ontology`（牌照类型/ISO20022/8583/辖区本体）与 `kb_org_profiles`。
- 串联：③ 卡片"查合规准入⑤"（按 org.country 触发）；⑤ 结果可关联到 ③ 机构。
- 联系人 enrich 走 Proxycurl（🟢 付费合规）；PII 落 `person.pii_ttl`。
- 接管队列：低置信(<0.6)研判进队列人工复核 + 反馈写回 `learnings`。

**交付产物**
- ③⑤ 两个 Agno Team/Workflow（代码 + verdict Pydantic schema）。
- 采集 Tools 实装：`web_fetch`(Firecrawl/Crawl4AI)、`regulator_fetch`、`search_web`、`people_enrich`。
- 前端页面：M3 研判页、M5 准入页、接管队列（可用）、概览雏形。
- 初始知识库内容 + 导入脚本（至少覆盖 2–3 个目标国监管）。
- **可运行 Demo 脚本 + 演示数据集**（对应 UI/UX 场景 A 的③⑤片段）。
- 评估集：≥20 条研判/准入的黄金样本 + 准确率/证据齐全率基线报告。

**验收标准（Exit Gate）**
- 真实机构名 → 60 秒内出带证据链的画像+切入点+风险；⑤ 出四类清单每条可溯源。
- ③→⑤ 串联无缝；低置信项正确进接管队列并可反馈。
- 证据齐全率 100%（无证据不展示）；核心样本人工评估通过率达约定阈值(如≥80%)。

**Demo**：输入某支付机构 + 目标国 → 现场生成研判卡与准入清单（真实数据、可点回原文）。

## P2 · 商机扩展：峰会④ + 行业情报①（媒体源）

**目标**：补齐"线索发现"，形成 ④→③→⑤ 串联链；上线每日情报早报。

**范围**
- ④ 峰会商机：上传/输入议程或名单 URL → 抽取机构/人 → ICP 规则打分 → 命中项落库 → **批量转③研判**。
- ① 行业情报（媒体源，🟢/🟡）：RSS/公开媒体(Finextra/The Paypers 等)采集 → SignalAgent 去噪提炼 → 每日 Top3 → 概览首屏 + 通知(飞书/Slack)。
- ICP 规则配置页；`watch_source` 源管理页。
- schedules：① 每日 cron 早报。

**交付产物**
- ④①两个 Workflow（代码 + schema）+ ICP 规则引擎（可配置行业/地区/规模/方向）。
- SignalAgent（去噪/观点提炼）+ `kb_sources` 可信源库。
- 前端：M4 峰会页、M1 情报流页、ICP 规则配置、源管理、通知设置。
- 通知集成（飞书/Slack Webhook）+ 每日早报模板。
- "没用/有用"反馈闭环（写回 `learnings`）。

**验收标准**
- 上传一份真实峰会名单 → 抽取+ICP 打分+批量转③ 打通。
- 每日早报按时自动产出并推送；情报可筛选、可反馈。
- ④→③ 串联的数据经 `org/person/insight` 贯通。

**Demo**：UI/UX 场景 A 全链路（④名单→③研判→⑤准入）+ 场景 C（每日早报）。

**合规提示**：①仅接入 RSS/公开媒体（🟢）；社媒深度抓取留到 P3/P4 评估。

## P3 · 获客⑥ + 招标②（安全子集）

**目标**：打通"发现→研判→触达"闭环的**合规安全子集**；高危能力默认关闭。

**范围**
- ⑥ 智能获客（🔴 但走安全子集）：OutreachAgent 基于③上下文生成个性化文案 + 意向研判；**发送前强制 Approval**；`ENABLE_M6_AUTOSEND=false` 时**只出草稿**；回复出现意向 → 进接管队列提醒人工。
- ② 招标监控（🔴 但走安全子集）：仅接入**公开社媒信号**；`GLiNER2` 抽取招标方/标的/金额/截止；线索默认进接管队列人工确认；`ENABLE_M2_GROUP_MONITOR=false`。
- schedules：② 高频 cron（公开信号）。

**交付产物**
- ⑥② 两个 Workflow + OutreachAgent + 意向研判逻辑。
- 触达文案模板 + 人工审批/编辑/升级 UI（M6 页）。
- 招标线索卡（倒计时）+ 误报反馈（写回 learnings）。
- feature flag 全量接入（默认安全值）+ 审计日志(`ingestion_log`/actions)。
- 合规子集说明页（关闭高危时的界面提示与降级行为）。

**验收标准**
- ⑥：生成引用③切入点的文案；无 flag 时不发送、仅进接管；意向识别→接管提醒可用。
- ②：公开信号命中→结构化线索→接管确认；群聊源关闭时界面正确提示。
- 所有高危动作留审计；flag 关闭为默认且经测试。

**Demo**：UI/UX 场景 B（招标安全子集）+ ③→⑥（文案+接管，不自动发送）。

## P4 · 高风险增强（可选做，需法务放行）

**目标**：在**法务评估通过 + 显式开启**前提下，启用高风险能力；否则本期跳过不影响平台可用。

**范围（均为可选、默认关闭）**
- ⑥ 自动发送：真人账号 + 限速拟人 + 账号池管理 + 熔断；开启需管理员 + 二次确认 + 审计。
- ② 群聊/私域招标监控：合规评估通过后接入；数据最小化 + TTL + 全程审计。
- 深度社媒抓取（①②）：官方 API 优先，twscrape/instaloader 兜底 + 限速 + 适配器熔断。

**交付产物**
- 限速/账号池/熔断组件 + 合规审计增强。
- **法务评估记录 + DPIA(数据保护影响评估) + 数据主体权利处理流程**。
- 灰度开关与回滚方案；风险监控看板。

**验收标准**
- 每项高危能力：默认关闭、开启留痕、可一键回滚；限速与熔断经压测。
- 有法务书面放行与 DPIA 归档，方可在生产开启。

**风险/缓解**：法律风险为主（hiQ/GDPR/平台 ToS）→ 若未获放行，**本期作为"能力预留"交付但不开启**，平台以安全子集正常运营。

## P5 · 硬化与运营化（GA）

**目标**：从"可演示"走向"可运营"。

**范围**
- 性能：抓取/研判并发、缓存(可选引入 Redis)、pgvector 索引调优、成本控制(本地小模型兜底)。
- 安全：RBAC、审计完备、密钥轮换、渗透测试、数据脱敏。
- 质量：Evals 体系(`agno_eval_runs`) + 回归集 + 幻觉/证据齐全率看板。
- 多租户/团队协作、指标看板(`agno_metrics`)、导出/报表。
- 可观测：告警、SLO、trace 采样、错误预算。
- 文档：运维手册、Runbook、用户指南。

**交付产物**
- 生产部署（IaC/编排）+ 监控告警 + 备份恢复演练。
- 评估报告 + 回归基线 + 效果指标看板。
- RBAC/多租户 + 完整审计。
- 用户手册 + 运维 Runbook + SLO 定义。

**验收标准**
- 达成约定 SLO（可用性/延迟）；关键路径有告警与回滚。
- Evals 回归通过；安全测试无高危项；备份恢复演练成功。

## 横向工作流（贯穿 P0–P5）

| 工作流 | 内容 | 落点 |
|---|---|---|
| **合规** | 数据源分级、PII TTL、feature flag、审计、DPIA(法务) | 合规网关 / `ingestion_log` / flags |
| **可观测** | traces/logs/metrics、告警、成本 | Agno traces/`agno_metrics` |
| **评估(Evals)** | 黄金样本、准确率/证据齐全率、幻觉监控 | `agno_eval_runs` + 回归集 |
| **安全** | 鉴权、密钥、RBAC、渗透 | BFF/AgentOS/PG |
| **反馈学习** | 误报/修正写回，越用越准 | Agno `learnings` |

## 里程碑与对外可演示节点

| 节点 | 时点 | 可演示内容 |
|---|---|---|
| **M-A 底座就绪** | P0 末 | 全栈打通 + InsightCard 渲染 + 调度/审批冒烟 |
| **M-B MVP（对外）** | P1 末 | ③研判 + ⑤准入 真实数据 + 串联（Issue 的 MVP 达标） |
| **M-C 串联链路** | P2 末 | ④→③→⑤ 全链路 + 每日情报早报 |
| **M-D 获客闭环** | P3 末 | 发现→研判→触达(安全子集) + 招标(公开信号) |
| **M-E GA** | P5 末 | 可运营：多租户/评估/监控/安全 |
| M-F 高风险 | P4（视法务） | ⑥自动发送 / ②群聊（放行后开启） |

> **对齐 Issue MVP 要求**：M-B 即满足"≥2 个模块端到端 + 真实数据"；M-C/M-D 覆盖"Agent 自动运转、端到端数据流通、模块串联"的加分项。

## 依赖与假设
- 依赖：LLM API 额度、Firecrawl/Proxycurl 账号、目标国监管站点可访问、飞书/Slack Webhook。
- 假设：团队 ~4 人；Agno 2.0 特性以官方文档为准（P0 spike 验证）；高风险模块以法务结论为最终门槛。
- 估算为相对工期，实际受数据源稳定性与评估阈值影响，按敏捷迭代滚动调整。
