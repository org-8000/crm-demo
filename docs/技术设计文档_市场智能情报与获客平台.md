# 市场智能情报与获客平台 — 技术设计文档（Technical Design Doc）

> 覆盖 6 大模块，共享同一技术底座。技术栈：**Python + Agno + Next.js(React) + PostgreSQL**。
> 设计原则：**组件少而精**、**共享底座**、**洞察即产出（带证据链）**、**Human-in-the-Loop**、**合规前置**。
> 版本：v1.0 ｜ 2026-08

---

## 1. 设计目标与约束

### 1.1 目标
- 用**一套底座**支撑 6 个模块（①行业情报 ②招标监控 ③客户画像研判 ④峰会商机 ⑤合规准入 ⑥LinkedIn获客）。
- **7×24 自动运转**（定时调度）+ **意向/风险出现时人工接管**（HITL）。
- 每条产出 = **结构化判断 + 置信度 + 证据链（可点回原文）**，而非原始数据堆砌。
- 模块可**串联**：④名单 → ③研判 → ⑤准入 → ⑥触达。

### 1.2 硬约束（技术偏好）
| 层 | 选型 | 说明 |
|---|---|---|
| Agent / 后端 | **Agno 2.0（AgentOS）** | AgentOS 本身是一个 FastAPI 应用，无需额外 Web 框架 |
| 前端 | **Next.js (React)** | 控制台、洞察卡片、人工接管队列 |
| 数据库 | **PostgreSQL + pgvector** | 关系数据 + 向量检索 + Agno 系统表，**单一数据源** |
| 语言 | **Python**（后端）/ **TypeScript**（前端） | — |

### 1.3 "少而精"的组件清单（核心仅 3 个进程）
```
1) Next.js 应用          —— 前端 + BFF（API 代理/鉴权）
2) AgentOS (FastAPI)     —— Agents / Teams / Workflows / 调度 / HITL / 知识库
3) PostgreSQL (+pgvector)—— 业务数据 + 向量 + agno_* 系统表（会话/记忆/审批/调度/追踪）
```
**外部依赖（非常驻进程，按需调用）**：LLM API（模型无关）、抓取工具（Firecrawl / Crawl4AI）、通知 Webhook（飞书/Slack）。
**刻意不引入**：不单独部署 Celery/Redis（用 Agno 内置 `schedules`）、不单独部署向量库（用 pgvector）、不单独部署 workflow 引擎（用 Agno `workflows`）。如后续量级需要，Redis 可作为可选缓存/队列增量引入。

## 2. 为什么这套栈能"少而精"——Agno 关键能力对齐

Agno 2.0 提供三个原语 **Agent / Team / Workflow**，并通过统一的 `db` 接口把以下能力落到**同一个 Postgres**：

| Agno 能力 | 对应 PG 表 | 满足的需求 |
|---|---|---|
| Sessions | `agno_sessions` | 会话/研判上下文延续 |
| Memory | `agno_memories` | 记住用户偏好/ICP、历史结论 |
| Learnings | `agno_learnings` | 从每次运行中沉淀经验 |
| Knowledge（PgVector 混合检索） | `agno_knowledge` + 向量表 | ⑤监管知识库、③企业资料 RAG |
| **Schedules（cron）** | `agno_schedules`, `agno_schedule_runs` | **7×24 自动运转（无需 Celery）** |
| **Approvals（HITL）** | `agno_approvals` | **意向/风险出现时人工接管** |
| Traces（OpenTelemetry） | `agno_traces`, `agno_spans` | 证据链/可观测/审计 |
| Metrics / Evals | `agno_metrics`, `agno_eval_runs` | 效果评估 |

> AgentOS 首次启动自动建表（`auto_provision_dbs`，生产可关闭自管 schema）；鉴权用 `OS_SECURITY_KEY`；PgVector 与业务数据同库，省一个组件。

这意味着"定时采集 + Agent 研判 + 人工接管 + 知识检索 + 审计"**全部内建**，我们只需写业务逻辑与前端。

```

   → 前端展示 / 人工接管 / 串联下一模块
```

## 4. 共享底座（Shared Foundation）——所有模块复用

> 底座 = **6 个横向能力 + 统一数据总线**。每个业务模块只是把这些能力用不同方式"编排"起来，几乎不重复造轮子。

### 4.1 采集 Tools 层（Ingestion Tools）
统一封装为 Agno `@tool`，供任意 Agent 调用；输出统一为 `RawDocument{source_type, url, fetched_at, content, raw_meta, legal_basis}`。

| Tool | 底层 | 服务模块 | 合规等级 |
|---|---|---|---|
| `web_fetch(url)` | Firecrawl / Crawl4AI → Markdown | ①③④⑤ | 🟢 低 |
| `search_web(query)` | 搜索 API | ①③④⑤ | 🟢 低 |
| `regulator_fetch(country)` | 监管官网适配器（Crawl4AI） | ⑤ | 🟢 低 |
| `social_fetch(account)` | 官方 API 优先 / twscrape·instaloader 兜底 | ①② | 🟡 中 |
| `group_monitor(source)` | 群聊/私域信号适配器 | ② | 🔴 高（可选做） |
| `people_enrich(name/url)` | Proxycurl（合规付费 API） | ③④⑥ | 🟢 低（付费换合规） |
| `linkedin_action(action)` | 真人账号 + 限速拟人 | ⑥ | 🔴 高（可选做） |

> **适配器模式**：每个 Tool 是可插拔适配器，数据源不稳定（如 Nitter 关停）时只换适配器，不动上层。

### 4.2 提取 Pipeline 层（Extraction）
统一把 `RawDocument` → `NormalizedEntity`（机构/人/牌照/金额/日期/事件…）。
- **确定性抽取**：`GLiNER2`（205M，CPU 可跑，零样本，schema 驱动）做实体/关系/结构化字段——便宜、可私有化。
- **LLM 兜底**：复杂语义/观点提炼用 LLM（模型无关），输出受 Pydantic schema 约束。
- 输出统一挂 `source_ref`（回指原文位置）→ 支撑证据链。

### 4.3 知识 / RAG 层（Knowledge，pgvector）
用 Agno `Knowledge` + `PgVector` 混合检索，多个知识库共享同一 PG：
- `kb_payment_ontology`：支付牌照类型、报文标准（ISO 20022/ISO 8583）、监管辖区本体 → ⑤③ 复用（**垂直护城河**）。
- `kb_org_profiles`：机构历史资料 → ③ 复用、避免重复研究。
- `kb_sources`：可信来源库（Finextra、The Paypers、监管官网清单）→ ①⑤。

### 4.4 Agent 原语层（Agents / Teams / Workflows）
可复用的"研究员"模板：
- `ResearchAgent`：给定实体+问题，`web_fetch`+RAG，输出结构化判断（③④⑤共用）。
- `SignalAgent`：给定源，过滤噪音+提炼观点/信号（①②共用）。
- `OutreachAgent`：给定目标+上下文，生成个性化触达 + 意向研判（⑥）。
- **Team**：多 Agent 协作（如 ③ = 采集Agent + 研判Agent + 风险Agent）。
- **Workflow**：确定性多步编排（cron 触发的采集→提炼→通知）。

### 4.5 Insight 对象模型（统一产出）
**所有模块产出同一结构**，前端一套卡片组件即可渲染：
```python
class Evidence(BaseModel):
    source_url: str
    source_type: str          # web|regulator|social|doc|linkedin
    snippet: str
    fetched_at: datetime

class Insight(BaseModel):
    module: str               # M1..M6
    subject: str              # 机构名/国家/线索标题
    verdict: dict             # 结构化判断（各模块 schema 不同）
    confidence: float         # 0~1
    risk_flags: list[str]     # 合规/数据来源风险标注
    evidence: list[Evidence]  # 证据链（必填）
    needs_human: bool         # 是否需人工接管
    created_at: datetime
```

### 4.6 合规网关（Compliance Gateway，横切）
- 采集前校验：来源是否公开合规、是否有 `legal_basis`、是否命中黑名单域。
- 存储：个人数据（PII）**最小化留存 + TTL + 可删除**；标注数据主体权利。
- 高风险模块（②⑥）默认 **feature flag 关闭**，需显式开启 + 审计。
- 所有采集写 `ingestion_log`（来源、时间、依据）→ 可审计。

## 5. 统一数据模型（PostgreSQL）

> 业务表 + Agno 系统表同库。以下为核心业务 DDL（Agno `agno_*` 表由 AgentOS 自动创建）。

```sql
CREATE EXTENSION IF NOT EXISTS vector;

-- 机构/客户（③④⑥ 共用）
CREATE TABLE org (
  id            BIGSERIAL PRIMARY KEY,
  name          TEXT NOT NULL,
  country       TEXT,
  domain        TEXT,
  business_lines TEXT[],
  created_at    TIMESTAMPTZ DEFAULT now(),
  UNIQUE (name, country)
);

-- 联系人（③④⑥，PII，受合规约束）
CREATE TABLE person (
  id          BIGSERIAL PRIMARY KEY,
  org_id      BIGINT REFERENCES org(id),
  full_name   TEXT,
  title       TEXT,
  linkedin_url TEXT,
  pii_ttl     TIMESTAMPTZ,          -- 到期自动清理
  legal_basis TEXT,                 -- 合规依据
  created_at  TIMESTAMPTZ DEFAULT now()
);

-- 被监控源（①② 共用：大V账号/媒体/群聊）
CREATE TABLE watch_source (
  id          BIGSERIAL PRIMARY KEY,
  module      TEXT,                 -- M1|M2
  source_type TEXT,                 -- twitter|linkedin|rss|group|regulator
  handle_or_url TEXT,
  enabled     BOOLEAN DEFAULT true,
  compliance_level TEXT,            -- green|yellow|red
  created_at  TIMESTAMPTZ DEFAULT now()
);

-- 统一洞察产出（六模块共用，前端统一渲染）
CREATE TABLE insight (
  id          BIGSERIAL PRIMARY KEY,
  module      TEXT NOT NULL,        -- M1..M6
  subject     TEXT,
  verdict     JSONB,                -- 各模块结构化判断
  confidence  REAL,
  risk_flags  TEXT[],
  evidence    JSONB,                -- Evidence[]
  needs_human BOOLEAN DEFAULT false,
  status      TEXT DEFAULT 'new',   -- new|reviewed|actioned|dismissed
  linked_org  BIGINT REFERENCES org(id),
  created_at  TIMESTAMPTZ DEFAULT now()
);
CREATE INDEX ON insight (module, status, created_at DESC);

-- 采集审计（合规）
CREATE TABLE ingestion_log (
  id          BIGSERIAL PRIMARY KEY,
  source_url  TEXT,
  source_type TEXT,
  legal_basis TEXT,
  fetched_at  TIMESTAMPTZ DEFAULT now()
);

-- 知识库向量（pgvector；Agno Knowledge 亦可托管）
CREATE TABLE kb_chunk (
  id          BIGSERIAL PRIMARY KEY,
  kb_name     TEXT,                 -- kb_payment_ontology|kb_org_profiles|kb_sources
  content     TEXT,
  embedding   VECTOR(1536),
  source_ref  JSONB
);
CREATE INDEX ON kb_chunk USING hnsw (embedding vector_cosine_ops);
```

**串联关系**：`insight.linked_org` + `person.org_id` 打通 ④→③→⑤→⑥ 数据流；④ 产出的名单落 `person/org`，③ 以其为 subject 研判，⑤ 按 `org.country` 出准入清单，⑥ 从高意向 `insight` 生成触达并进 `agno_approvals` 等人工接管。

## 6. 六大模块实现

> 每个模块 = 复用 §4 底座 + 一个 Agno Workflow/Team。下方给出：触发方式、流程、复用点、产出 `verdict` schema、合规标注。

### 模块① 行业情报采集　🟡 中风险（社媒部分可选做）
- **触发**：`schedule`（每日 cron）。
- **流程**：`social_fetch`/`search_web` 拉取被监控源 → `SignalAgent` 去噪+提炼独特认知/大V观点 → 排序取 Top3 → `Insight` → 通知。
- **复用**：采集Tools①、提取Pipeline、`kb_sources`、SignalAgent、Insight、通知。
- **verdict**：`{headline, unique_insight, kol_view, why_it_matters, rank}`
- **合规**：RSS/公开媒体🟢；社媒抓取🟡（限速+官方API优先）。深度社媒监控可作为**可选增强**。

### 模块② 招标信息监控　🔴 高风险（群聊数据源可选做）
- **触发**：`schedule`（高频 cron）。
- **流程**：`social_fetch`/`group_monitor` → `GLiNER2` 抽取（招标方/金额/截止/标的）→ `ResearchAgent` 结构化核实 → `Insight`(needs_human=true) → **实时通知 + Approval**。
- **复用**：采集Tools①②、提取Pipeline、ResearchAgent、Approval、通知。
- **verdict**：`{tender_org, scope, deadline, amount, source_confidence}`
- **合规**：🔴 **群聊/私域监控合规风险最高，默认关闭**，需法务评估 + 显式开启 + 全程审计。社媒公开信号部分可先做。

### 模块③ 客户画像与商机研判　🟢 低风险（MVP 首选）
- **触发**：手动输入机构名 / 上游④批量。
- **流程**：`web_fetch`+`search_web`+`people_enrich` → RAG(`kb_org_profiles`) → **Team**（采集Agent+研判Agent+风险Agent）→ 画像卡片+切入点+风险 → `Insight`。
- **复用**：采集Tools、提取Pipeline、`kb_org_profiles`/`kb_payment_ontology`、ResearchAgent Team、Insight。
- **verdict**：`{profile, business_focus, entry_points[], risks[], fit_score}`
- **合规**：公开企业信息🟢；联系人 PII 走 `person.pii_ttl` + Proxycurl 合规源。

### 模块④ 峰会商机挖掘　🟢 低风险
- **触发**：手动上传/输入峰会官网或议程 URL。
- **流程**：`web_fetch` 解析议程/嘉宾 → `GLiNER2` 抽取机构/人/职务 → 匹配 ICP 规则 → 命中者落 `org/person` → **可一键批量转③研判**。
- **复用**：采集Tools、提取Pipeline、ICP 匹配、Insight、与③串联。
- **verdict**：`{attendee_org, role, business_direction, icp_match, recommended_action}`
- **合规**：公开议程/名单🟢；联系人 PII 同③。

### 模块⑤ 合规准入筛查　🟢 低风险（MVP 首选）
- **触发**：手动输入 `目标国家 + 业务模式`。
- **流程**：`regulator_fetch(country)` + RAG(`kb_payment_ontology`) → `ResearchAgent` 生成准入清单 → `Insight`（每条附监管原文证据）。
- **复用**：采集Tools、Docling/提取、`kb_payment_ontology`（护城河）、ResearchAgent、Insight。
- **verdict**：`{licenses[], messaging_standards[], data_compliance[], business_restrictions[], readiness_summary}`
- **合规**：监管官网公开信息🟢。**独立高价值（对标 Vixio）**。

### 模块⑥ LinkedIn 智能获客 Agent　🔴 高风险（自动触达可选做）
- **触发**：从③/④ 高 `fit_score` 目标进入队列。
- **流程**：`OutreachAgent` 生成个性化触达（带③研判上下文）→ 发送前进 **Approval（人工确认文案）**→ `linkedin_action` 真人账号限速发送 → 监测回复 → **意向出现 → Approval 升级人工接管**。
- **复用**：采集Tools（enrich）、OutreachAgent、**Approval(HITL)**、Insight、与③④串联。
- **verdict**：`{message_draft, intent_level, next_step, handoff_to_human}`
- **合规**：🔴 **LinkedIn 自动化违反其 ToS/封号风险**（hiQ 案定调）。**默认：只做"文案生成 + 意向研判 + 人工接管"，自动发送作为可选**；enrich 用 Proxycurl；不做大规模抓库。

## 7. 合规风险矩阵（哪些"可选做"）

| 模块 | 数据源 | 风险 | 默认策略 | 可选增强（需法务+flag+审计） |
|---|---|---|---|---|
| ③ 客户画像研判 | 公开企业信息/监管 | 🟢 低 | **默认开启** | — |
| ⑤ 合规准入筛查 | 监管官网 | 🟢 低 | **默认开启** | — |
| ④ 峰会商机 | 公开议程/名单 | 🟢 低 | **默认开启** | 联系人 enrich（Proxycurl，付费合规） |
| ① 行业情报 | RSS/媒体 + 社媒 | 🟡 中 | 媒体开启 | **社媒深度抓取（可选）** |
| ⑥ LinkedIn 获客 | LinkedIn | 🔴 高 | 仅文案+研判+接管 | **自动发送/规模化触达（可选）** |
| ② 招标监控 | 社媒 + 群聊 | 🔴 高 | 公开社媒信号 | **群聊/私域监控（可选，高危）** |

**统一控制**：每个高风险能力用环境变量 feature flag（如 `ENABLE_M2_GROUP_MONITOR=false`、`ENABLE_M6_AUTOSEND=false`），关闭时模块仍可运行"合规子集"。

## 8. 部署与运行

### 8.1 组件（3 个常驻 + 依赖）
```
docker compose:
  ├─ web        : Next.js (React)                 :3000
  ├─ agentos    : Python/Agno AgentOS (FastAPI)   :8000
  └─ postgres   : postgres:16 + pgvector          :5432
env: OPENAI/ANTHROPIC_API_KEY, FIRECRAWL_API_KEY, PROXYCURL_API_KEY,
     OS_SECURITY_KEY, DATABASE_URL, ENABLE_M2_*, ENABLE_M6_*
```

### 8.2 AgentOS 启动（示意）
```python
# app/agent_os.py
from agno.os import AgentOS
from agno.db.postgres import PostgresDb
from modules import m1_intel, m3_profile, m5_compliance   # 各模块 Team/Workflow
from modules import m2_tender, m4_summit, m6_outreach

db = PostgresDb(db_url=os.environ["DATABASE_URL"])   # 业务+系统表同库

agent_os = AgentOS(
    teams=[m3_profile.team, m1_intel.team],
    workflows=[m5_compliance.wf, m4_summit.wf, m2_tender.wf, m6_outreach.wf],
    db=db,                       # sessions/memory/knowledge/schedules/approvals/traces
    # auto_provision_dbs=False,  # 生产自管 schema
)
app = agent_os.get_app()         # FastAPI app
```

### 8.3 7×24 调度（Agno schedules，替代 Celery）
```python
# 每日 08:00 跑行业情报，每 30 分钟跑招标监控（若开启）
m1_intel.wf.schedule(cron="0 8 * * *")
if os.getenv("ENABLE_M2") == "true":
```

### 8.5 前端（Next.js）职责

## 附：关键取舍说明
- **用 Agno schedules 而非 Celery/Redis**：减少一个常驻组件与一套运维；量级上来再引入 Redis 作可选队列。
- **用 pgvector 而非独立向量库**：知识与业务同库，简化备份/事务/运维。
- **AgentOS = FastAPI**：后端 API 与 Agent 运行时合一，不再单独搭 Web 框架。
- **GLiNER2 做确定性抽取**：降低 LLM 成本与幻觉，可私有化，适合 PII/结构化字段。
- **合规为一等公民**：网关 + feature flag + 审计 + PII TTL，把 🔴 模块设计成"可选做且默认安全子集"，而非事后补救。
